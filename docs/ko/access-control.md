# 접근 제어

[English](../access-control.md) | **한국어**

PKB는 호출자마다 읽고 쓸 수 있는 범위를 제한할 수 있습니다. 검색, 문서·파일 읽기, 목록과 개수, 미디어, 개념 그래프까지 모든 읽기 경로에 이 제한이 걸립니다. 이 문서는 모델, 경로별 적용 방식, 아직 새는 부분, 운영 방법, 개인이 아니라 회사가 쓸 때 설계가 어떻게 바뀌는지를 다룹니다.

구현은 `src/pkb/access.py`(정책·주체·ES 필터·감사 로그)와 `src/pkb/graph/visibility.py`(그래프 뷰)에 있고, 테스트는 `tests/test_access*.py`입니다.

## 모드

| `ACCESS_POLICY` | 동작 |
| --- | --- |
| 비어 있음(기본) | 단일 사용자 모드입니다. 인증 없이 모든 호출이 내장 관리자 `system`으로 실행됩니다. 이 기능을 넣기 전과 같습니다. |
| YAML 파일 경로 | MCP 요청마다 `Authorization: Bearer <토큰>`이 필요합니다. 토큰으로 주체를 정하고, 경로 규칙이 그 주체가 읽고 쓸 수 있는 범위를 정합니다. 어떤 규칙도 허용하지 않은 자원은 거부합니다. |

파일을 지정했는데 읽거나 해석할 수 없으면 서버가 뜨지 않고, 실행 중인 서버는 모든 요청을 거부합니다(fail closed).

## 모델

- **자원**: doc_id 형식의 경로입니다(`data/…`, `obsidian/…`, `attachments/…`). 파일, 색인 청크, 문서 행, 미디어, 그래프 근거가 모두 이 경로를 가집니다.
- **주체**: `principals` 아래 항목입니다. `groups`, `admin`, Bearer 토큰의 SHA-256 해시를 둘 수 있습니다.
- **대상**(규칙 목록에 쓰는 이름): `user:<id>`, `group:<이름>`, `*`(인증된 모든 주체).
- **규칙**: `path`와 `read`·`write` 대상 목록입니다. 자원에 맞는 규칙 중 가장 긴 것 하나만 결정하므로, 하위 폴더 규칙이 상위 규칙을 허용·거부 어느 쪽으로든 덮어씁니다. `path`는 경로 성분 단위로 맞춥니다. `data/career`는 `data/career/x.md`에는 맞지만 `data/careerist.md`에는 맞지 않습니다. `default`는 그 밖의 모든 자원에 쓰는 규칙이고, 생략하면 기본 거부입니다.
- `write`는 `read`를 포함합니다. 편집자가 diff와 `expected_hash`를 받으려면 파일을 읽어야 하기 때문입니다.
- `admin: true` 주체는 규칙을 건너뛰고 관리 도구를 부를 수 있습니다.

```yaml
version: 1
default:            # 어떤 규칙에도 맞지 않는 자원. 생략하면 거부
  read: [group:owner]
  write: [group:owner]
principals:
  jk:
    groups: [owner]
    admin: true
    token_sha256: <jk 토큰의 sha256>
  study-agent:
    groups: [study]
    token_sha256: [<해시>, <교체 중인 새 토큰 해시>]
rules:
  - path: data/study
    read: [group:owner, group:study]
  - path: data/study/private      # 가장 긴 규칙이 이긴다: 하위 폴더를 다시 닫는다
    read: [group:owner]
  - path: data/career
    read: [user:jk]
    write: [user:jk]
```

규칙을 frontmatter가 아니라 경로에 두는 이유는 세 가지입니다. 바이너리·첨부·미디어에는 frontmatter가 없습니다. 쓰기 권한자가 문서를 편집해 읽기 대상을 넓힐 수 있으면 안 됩니다. 그리고 규칙을 바꾸면 재색인 없이 다음 요청부터 적용됩니다.

## 적용 지점

| 경로 | 방식 |
| --- | --- |
| 하이브리드 검색(BM25 + kNN + 이웃 청크), 미디어 kNN, 관련 문서, 문서 조회 | 정책을 Elasticsearch 필터 하나로 번역(`Policy.es_filter`)하고, `_search_filters`가 결합 전에 BM25 `bool.filter`와 `knn.filter` 양쪽에 붙입니다. 순위를 매기기 전에 거르므로 상위 k개가 읽을 수 있는 청크로만 채워집니다. 결과를 받은 뒤에 거르면 k개보다 적게 남습니다. |
| 결과 목록 | 모든 결과를 `access.readable()`로 한 번 더 검사합니다. 여기서 걸러지는 행이 있다면 번역한 필터가 정책과 어긋난 것이므로 경고도 남깁니다. |
| `list_documents`, `list_categories` | 같은 필터를 본 질의에 넣어 집계가 읽을 수 있는 문서만 세게 합니다. |
| `read_file`, `get_file`, `list_files`, `write_file`, `patch_file`, 첨부, `get_media`, 아카이브·복구·재색인 | 파일이 있는지 보기 전에 `require()`로 권한부터 검사합니다. 거부된 자원과 없는 자원은 같은 문장을 돌려주므로 존재 여부를 떠볼 수 없습니다. |
| 개념 그래프 도구 | `graph_read_connection`이 그래프 테이블과 같은 이름의 TEMP 뷰를 만들어 main 테이블을 가립니다(SQLite는 한정자 없는 이름을 temp에서 먼저 찾습니다). 기존 조회 코드는 고치지 않아도 걸러진 그래프를 읽고, 뷰라서 쓰기는 거부됩니다. |
| 도구 등급 | 모든 MCP 도구를 `read`·`write`·`admin` 중 하나로 선언합니다(`@tool_access`). 등급이 없는 도구가 있으면 테스트가 실패합니다. admin 도구는 동기화, 변환, doctor, 그래프 추출·큐레이션·병합입니다. |
| 신원 | MCP SDK의 `TokenVerifier`(`PolicyTokenVerifier`)를 씁니다. 주체는 토큰에서만 정하고 도구 인자에서는 받지 않습니다. 요청마다 정책을 다시 읽으므로 주체·토큰 해시·그룹 소속을 빼면 바로 적용됩니다. |
| 감사 | `<DATA_ROOT>/.logs/access.jsonl`에 도구 호출(주체, 도구, 등급, 판정)과 거부된 자원을 남깁니다. 문서 내용은 남기지 않습니다. `.logs`는 숨김 폴더라 어떤 파일 도구로도 읽을 수 없습니다. |

### 대소문자를 구분하지 않는 파일시스템

macOS 기본 파일시스템은 `data/CAREER/x.md`로도 `data/career/x.md`를 엽니다. 요청 문자열을 그대로 규칙과 비교하면 대소문자만 바꿔 거부 규칙을 피할 수 있습니다. 그래서 파일 기반 검사는 실제 디렉터리 항목 이름으로 자원 경로를 다시 만들고, NFC로 맞춘 뒤 비교합니다. 기존 항목과 대소문자만 다른 요청은 거부합니다. `..`와 빈 성분은 규칙과 비교하기 전에 거부합니다.

### 그래프 가시성 규칙

개념 그래프는 여러 문서에서 뽑아 만든 데이터입니다. 결과 목록만 걸러서는 설명·별칭·개수·경로를 통해 비공개 문서가 드러납니다.

- 언급, 관계 근거, 문서 행, 추출 마커는 `doc_id`를 읽을 수 있는 행만 보입니다.
- 개념은 읽을 수 있는 언급이나 관계 근거가 하나라도 있으면 보입니다. 이름·slug·범주·종류는 그 청크에서 바로 나온 값이라 보여 줍니다. 설명·임베딩·별칭·증류 산문은 여러 문서를 합친 값이라, 그 개념의 근거를 *전부* 읽을 수 있을 때만 보입니다. 새 열은 `PUBLIC_CONCEPT_COLUMNS`에 넣기 전까지 숨깁니다(fail closed).
- 관계는 읽을 수 있는 근거가 있을 때만 보이고, `weight`·`evidence_count`·`confidence`를 그 근거로 다시 계산합니다.
- 추이 관계 추론은 보이는 그래프 위에서만 계산하므로 모든 전제가 보이는 관계입니다.
- 별칭 충돌 기록은 숨깁니다.

미디어 검색 결과에도 같은 규칙을 씁니다. 미디어 청크의 맥락은 그 파일을 넣은 노트들에서 오므로, 연결된 노트를 전부 읽을 수 있을 때만 맥락을 보여 주고 `linked_from`에는 읽을 수 있는 노트만 남깁니다.

## 아직 새는 부분 (알려진 한계)

- **BM25 통계**: IDF를 샤드 전체로 계산하므로, 점수에 숨긴 문서 중 몇 개가 그 단어를 담는지에 대한 약한 신호가 섞입니다. Elasticsearch DLS에도 같은 한계가 있고, 없애려면 색인을 분리해야 합니다.
- **admin은 모든 권한을 가집니다**: 내용을 읽지 않고 동기화만 하는 운영자 역할은 없습니다.
- **정적 토큰에는 만료가 없습니다.** 새 해시를 추가한 뒤 옛 해시를 빼는 방식으로 교체합니다.
- **감사 로그 쓰기가 실패해도 요청은 막지 않습니다.**
- **프롬프트 주입**: 신뢰도가 낮은 주체가 공유한 문서에 지시문이 들어 있을 수 있습니다. PKB는 instructions에서 검색 내용을 데이터로 다루라고 표시하지만, 실제로 그렇게 다루는 것은 클라이언트의 몫입니다.
- **항목별 ACL**(frontmatter나 커넥터가 주는 ACL)은 없습니다. 아래 2단계를 보세요.

## 운영

```bash
uv run pkb access token                              # 새 토큰과 그 sha256 출력
uv run pkb access show                               # 주체, 규칙, 규칙별 색인 문서 수 (0이면 경로 오타)
uv run pkb access check data/career/cv.md -p study-agent
uv run pkb --as study-agent query "hybrid search"    # 그 주체가 보는 결과 (읽기 명령만)
```

1. 정책을 쓰고 토큰 해시만 넣습니다. 토큰 원문은 각 클라이언트의 MCP 설정(`Authorization: Bearer …`)에만 둡니다.
2. `ACCESS_POLICY=/경로/access.yml`을 설정합니다. 클라이언트가 다른 주소로 접속하면 `MCP_PUBLIC_URL`도 설정합니다. 그다음 MCP 서버를 재시작합니다.
3. 클라이언트는 `whoami`로 자기 주체와 허용 규칙을 확인할 수 있습니다.

PKB 앞에 게이트웨이가 있으면 PKB는 게이트웨이가 보낸 토큰을 인증합니다. 게이트웨이가 모든 사용자에게 PKB 토큰 하나를 쓰면 그 사용자들은 한 주체가 됩니다. 사용자별로 제한하려면 사용자별 토큰이 PKB까지 와야 하고, 아니면 게이트웨이에서 토큰을 교환해야 합니다(1단계 참고).

## 회사 단위로 확장할 때

단일 머신 설계에는 다음 단계들이 갈아 끼우는 지점이 하나 있습니다. "이 주체"를 "이 자원들"로 바꾸는 함수(`Policy.es_filter`, `Policy.allows`)입니다. 아래 표는 단계마다 바뀌는 것을 정리한 것입니다.

| 단계 | 신원 | ACL 출처 | 적용 | 권한 회수 |
| --- | --- | --- | --- | --- |
| 0 — 현재 | 해시로 저장한 정적 토큰 | 파일 하나의 경로 규칙 | 번역한 ES 사전 필터 + 행 단위 재검사, 그래프 뷰 | 다음 요청 |
| 1 — 팀 | OIDC IdP(Keycloak, Entra ID, Okta). JWT `TokenVerifier`가 JWKS 서명, `iss`, `exp`, 이 서버에 묶인 `aud`/resource(RFC 8707)를 검사하고 수명이 짧은 토큰을 씁니다. 그룹은 토큰 클레임만 믿지 않고 디렉터리에서 가져옵니다. Entra는 그룹이 200개를 넘으면 목록 대신 초과 표시를 보냅니다. | 같은 규칙에 IdP 그룹 | 같음 | 그룹 변경은 즉시, 토큰은 수명 안에서 |
| 2 — 회사 | SCIM(RFC 7644) 디렉터리 동기화 | 커넥터가 SharePoint, Drive, Confluence, Slack의 ACL을 항목마다 주체·그룹 id로 가져옵니다(구성원 목록으로 펼치지 않음). 경로 규칙은 상한이 됩니다. | 항목 ACL id를 모든 청크에 복제(`acl_read` keyword)하고, 호출자의 그룹을 펼쳐 `terms` 필터로 맞춥니다. 거부 항목이 이깁니다. 민감한 도구는 읽는 시점에 다시 검사합니다. | 출처마다 SLA를 정합니다(예: 15분 이내). 신원 회수는 즉시입니다. |
| 3 — 전사 | 같음, 더해 CAEP/SSF 세션 회수 | 계층과 공유는 중앙 ReBAC(OpenFGA, SpiceDB), 분류 등급 같은 속성은 ABAC(Cedar, OPA 부분 평가) | 인가 서비스의 변경 피드로 로컬 ACL 색인을 채우고, 반환 항목을 마지막에 다시 검사합니다(OpenFGA "search with permissions" 2안). 강한 격리가 필요하면 테넌트별 색인이나 클러스터를 씁니다. ES DLS(Enterprise 라이선스)는 두 번째 방어선입니다. | 일관성 토큰(Zanzibar zookie)으로 new-enemy 문제를 막습니다. |

검색 밖에서 단계마다 더해지는 것:

- **게이트웨이**: 클라이언트 토큰을 PKB로 그대로 넘기지 않습니다(MCP는 토큰 전달을 금지합니다). PKB를 대상으로 하는 토큰으로 교환하거나(RFC 8693), 게이트웨이를 인증한 뒤 서명한 사용자 단언을 넘깁니다.
- **파생 데이터**: 위 그래프 규칙을 요약, 중심 벡터, 개수, 캐시 같은 모든 집계에 적용합니다. 여러 문서를 합친 요약은 원본 ACL들의 *교집합*을 물려받습니다. 캐시 키에는 주체 집합과 정책 버전을 넣습니다.
- **로그·평가셋**: 질의와 본문 조각이 들어 있으므로 관리자 전용 데이터로 보고 보존 기간을 따로 정합니다. 감사 로그는 추가만 되는 저장소나 SIEM으로 보냅니다.
- **그대로 가져갈 테스트**: 무작위 정책에서 번역한 필터와 정책 판정이 같은 집합을 고르는지(`test_es_filter_selects_exactly_the_allowed_documents_on_random_policies`), 제한 문서에 넣은 카나리 문자열이 어떤 도구 출력에도 나오지 않는지, 모든 도구가 등급을 선언했는지, 숨긴 문서를 바꿔도 다른 주체의 결과가 점수 변동 말고는 바뀌지 않는지(비간섭).

트레이드오프:

| 방식 | 얻는 것 | 대가 |
| --- | --- | --- |
| 정책을 필터로 번역(0단계) | ACL 복제가 없고 회수가 즉시 적용됨 | 정책이 경로 형태이고 작을 때만 맞음 |
| 항목 ACL 복제(2단계) | ACL이 수백만 가지여도 정확한 상위 k와 낮은 지연 | ACL이 마지막 동기화만큼만 최신 |
| 정책 엔진으로 검색 결과를 사후 검사 | 늘 최신 | 상위 k가 줄고 지연이 늘어남 |
| 테넌트별 색인 | 강한 격리, IDF 부채널 제거 | 운영 부담, 테넌트 간 검색 불가 |
| ES 문서 수준 보안 | 엔진 안에서 적용 | 유료 라이선스, 사용자별 역할이나 API 키 |
