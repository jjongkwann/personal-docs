# Windows Ollama 임베딩

임베딩은 문서와 질문을 같은 의미 공간의 숫자 벡터로 바꾼다. 검색은 벡터의 유사도와
키워드 검색을 함께 사용한다. 답변·요약·개념 관계 추출은 별도의 생성 모델이 담당한다.

## 설정에서 선택

1. PKB 자료함의 **설정 → 검색 임베딩**에서 Ollama IP 또는 URL을 입력한다.
   예: `192.168.0.2` 또는 `http://192.168.0.2:11434`.
2. **모델 확인**을 누른다. PKB 서버가 `/api/tags`와 `/api/show`를 읽고 임베딩 모델만 표시한다.
   하나면 자동 선택하며, 여러 개면 목록에서 고른다. 모델은 Windows에 미리 설치되어 있어야 한다.
3. **적용하고 재색인**을 누른다. 실제 출력 차원과 모델 digest를 확인한 뒤 새 검색 색인과
   그래프 사본을 만든다. 상태의 `chunks`는 검색 청크, `concepts`는 개념 벡터 단계다.
4. 완료되면 **현재 사용 중**이 새 서버·모델로 바뀐다. 설정 화면을 닫아도 서버 작업은 계속된다.

현재 검증한 모델은 `embeddinggemma-2:740m`, 출력 768차원이다. 생성 설정의
`gemma4:12b-it-qat`와 역할이 다르다. 문맥·출력 옵션을 앱에서 임의로 덮어쓰지 않으며,
임베딩 입력도 자동으로 잘라 버리지 않는다. 너무 긴 입력이나 잘못된 벡터는 실패로 보고한다.

재색인 중에는 일반 검색·쓰기·자동 그래프 처리가 잠시 멈춘다. 임베딩 상태 조회는 가능하다.
다른 PKB 작업이 실행 중이면 시작 요청이 busy로 거절될 수 있다. 상태에 새 작업이 없는지
확인하고 해당 작업이 끝난 뒤 다시 적용한다. 통신 응답이 유실된 경우에도 먼저 상태를 확인한다.

## 기존 자료 보존

- 원본 파일, 청크 ID·본문·메타데이터, 개념·관계·근거 기록을 보존한다.
- 텍스트 청크와 개념 벡터를 새로 계산하고 문서 단위 검색 색인을 다시 만든다.
- 검증된 EmbeddingGemma 2 / 768 공간의 기존 이미지·오디오 벡터는 그대로 복사한다.
  현재 호환성 허용 digest는 `f4981a15b99858ad1f2e0729416e526be7b4f428291b40082b9e4f7b27b5f62f`다.
  같은 아키텍처라는 이유만으로 다른 가중치의 벡터를 호환된다고 보지 않는다.
- 기존 미디어와 호환되지 않는 모델은 자료를 삭제하지 않고 전환을 중단한다. 다른 벡터 공간의
  미디어 전체 변환은 이 설정 기능의 지원 범위가 아니다.
- 새 이미지·오디오의 `pkb media-sync`는 PKB가 알려 주는 활성 backend로 처리한다.
  Ollama 선택 시 이미지와 오디오를 Windows에 보내고 로컬 모델로 대체 실행하지 않는다.
- 기존 물리 색인과 그래프는 완료 후에도 남는다. 재색인 완료는 개념·관계 **추출** 완료와 다르다.

## 저장 위치와 장애 확인

초기 `.env`의 `GRAPH_DB_PATH` 부모에 `.embedding-runtime/`을 둔다.

| 파일 | 의미 |
|---|---|
| `active.json` | 실제 활성 설정과 이전 설정(`previous`). 색인·그래프 경로를 함께 전환한다 |
| `job.json` | 최신 작업의 상태·단계·진행 수·오류 |
| `request-<id>.json` / `job-<id>.log` | 작업 입력 구성과 실행 로그 |
| `graph-<id>.sqlite` | 새 개념 벡터를 담은 그래프 사본 |

Elasticsearch의 새 물리 색인은 `pkb_embedding_<id>`와 그 `_docs` 색인이다. MCP, CLI,
자동 그래프 worker는 작업을 시작할 때 활성 manifest를 읽는다. 기존 ES alias는 이전 색인을
가리킨 채 보존하므로 외부 도구에서 alias만 조회하면 이전 자료를 보게 된다.

선택 후 `.env`의 `GRAPH_DB_PATH`를 새 그래프 경로로 바꾸면 runtime 디렉터리도 달라지므로
바꾸지 않는다. `.env`의 모델/색인 값을 편집하는 것은 앱에서 선택한 활성 구성을 바꾸는 방법이 아니다.

실패하면 이전 구성이 계속 활성이고 부분 생성된 저장소도 보존한다. 원인을 해결한 뒤 다시
적용하면 새 작업을 만든다. 중단된 프로세스는 다음 상태 조회에서 실패로 표시한다.
작업 중 모델 태그의 digest가 바뀌면 서로 다른 벡터가 섞이지 않도록 중단한다.

운영 복구가 필요하면 먼저 서버·worker·CLI 쓰기를 중지하고 manifest, job 파일과 두 저장소를
보관한다. `previous`에 기록된 구성으로 `active.json`을 원자적으로 교체한 뒤 서비스를 재시작하고
상태·검색을 확인한다. 첫 전환의 이전 구성이 `.env`와 같다고 확인된 경우에만 manifest를 별도
보관 위치로 옮겨 초기 구성을 사용한다. 기존 색인이나 그래프를 삭제하는 절차는 포함하지 않는다.

API: [Ollama embed](https://docs.ollama.com/api/embed).
